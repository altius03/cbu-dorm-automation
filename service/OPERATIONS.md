# 로컬 서비스 운영

## 계정과 신청 처리

- 학번과 비밀번호는 현재 브라우저 페이지와 현재 API 요청에서만 사용하며 SQLite에 저장하지 않습니다.
- SQLite에는 계정 HMAC, 세션 토큰 해시, 신청 결과와 운영 일정만 저장합니다.
- 새로고침·브라우저 재실행 뒤에는 다시 로그인해야 합니다. 로그인하면 같은 계정 HMAC의 이전 작업
  기록을 이어서 볼 수 있고 이전 세션 토큰은 무효화됩니다.
- 신청은 현재 요청에서 최대 4분 동안 처리합니다. 강제 종료 뒤 `running` 작업은 `interrupted`로
  바꾸며 자동 재신청하지 않습니다.
- 저장 직전 `unknown`을 기록하고 학교 조회로 완료가 확인된 경우에만 `saved`로 바꿉니다.
- 연속일은 학교 제한에 맞춰 최대 7박 8일씩 묶습니다.

## 실행

```sh
npm run service
```

기본 주소는 `http://127.0.0.1:8787`입니다. 원격 HTTPS에서는 실제 주소와 보안 쿠키를 설정합니다.

```sh
OVERNIGHT_PUBLIC_ORIGIN="https://서비스주소" OVERNIGHT_SECURE_COOKIE=1 npm run service
```

`OVERNIGHT_MASTER_KEY`는 Base64 32바이트 서버 키이며 계정 HMAC과 세션 보호에 사용합니다.
기존 DB에서는 같은 키를 계속 사용해야 합니다. 키·토큰·학교 로그인 정보는 로그나 문서에 넣지 않습니다.

기존 암호문 스키마를 처음 열면 현재 키로 계정 HMAC을 만든 뒤 `credential_ciphertext` 컬럼을 제거하고
WAL을 비우며 DB를 `VACUUM`합니다. 키가 맞지 않으면 변경을 롤백하고 시작을 거부합니다.

## 백업과 복구

실행 중인 SQLite도 WAL을 포함해 온라인 백업할 수 있습니다. 목적지는 원본 밖의 새 폴더여야 합니다.

```sh
node service/backup.mjs /absolute/path/to/new-backup-directory
```

백업은 DB 무결성과 서버 키 지문을 확인한 뒤 `manifest.json`을 마지막에 기록합니다. 로컬
`master.key`가 있으면 함께 보존하고, 환경변수 키는 파일로 내보내지 않습니다. 복구할 때는 원본과
백업을 모두 보존한 채 새 폴더에서 같은 서버 키로 실행합니다.

## 검증

```sh
npm run test:service
```

자동 테스트는 임시 DB와 가짜 학교 포털만 사용합니다. 기존 암호문 컬럼 제거, 비밀번호 미저장,
로그인·달력·일괄신청·확인 필요 결과 복구, 실제 로컬 HTTP 보안 헤더와 모바일 UI를 검증합니다.
