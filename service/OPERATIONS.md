# Auto_Overnight 운영 메모

2026-09-19 기준. 로컬 웹 서비스는 Node.js 24의 기본 모듈만 사용하며 추가 의존성 설치가 필요 없다.

## 계정과 신청 처리

- 포털 로그인 아이디·비밀번호는 AES-256-GCM으로 저장한다. 시작할 때 기존 암호문과 키를 검증하며,
  키가 없거나 맞지 않으면 실행을 거부한다. 마이그레이션은 기존 프로필 ID·토큰 해시·암호문을 유지한다.
- 최초 연결 토큰은 한 번만 사용하며 사용 기록은 재시작 뒤에도 유지한다. 연결 응답을 잃거나
  로그아웃했다면 `저장된 계정 다시 연결`에서 포털 로그인 아이디·비밀번호를 재검증한다. 기존 프로필과
  작업 기록을 유지하면서 비밀번호를 갱신하고 이전 세션 토큰을 무효화한다.
- 로그아웃은 서버 토큰과 브라우저 쿠키를 무효화한다. 저장된 계정과 기록은 남는다.
  계정 삭제는 저장된 계정과 관련 작업 기록을 삭제하며, 신청 처리 중에는 거부한다.
- 단건과 일괄신청 모두 UUID 작업을 SQLite에 먼저 저장한다. 같은 UUID 재접수는 기존 작업을
  반환하므로 HTTP 응답 유실 뒤에도 중복 실행하지 않는다. 다른 날짜의 새 신청에는 새 UUID를 사용한다.
- 일괄신청은 날짜 입력 없이 `앞으로 30일 매일`, `앞으로 1주 주말`, `앞으로 30일 주말`,
  `이번 학기 남은 주말`을 제공한다. 토·일을 각각 하루씩 신청하며 한국 시간의 마감된 당일은 제외한다.
  학기 말은 공식 학사 일정 연동이 아닌 6월 30일/12월 31일 기준이다.
- 일괄 미리보기는 계정·날짜에 묶인 서명으로 10분간 고정한다. 저장 전 중복·겹침을 확인하고
  저장 응답이 유실되면 재전송 없이 조회로 결과를 확인한다. 불명확한 건은 `확인 필요`로 남기고
  후속 요청을 중단한다.
- 새로고침 후 결과를 복구하고 최근 작업 10개를 선택해 조회할 수 있다. `중단`은 확인창 없이
  즉시 중단 요청을 보낸다. 현재 요청의 결과를 확인한 뒤 남은 요청을 멈추며, 이미 학교에
  접수된 외박을 취소하지 않는다.

## 실행과 보호 범위

저장소 루트에서 `npm run service`로 실행한다. 기본 주소는 `http://127.0.0.1:8787`이다.
원격 HTTPS 접속은 실제 주소에 맞춰 다음처럼 설정한다.

```sh
OVERNIGHT_PUBLIC_ORIGIN="https://서비스주소" OVERNIGHT_SECURE_COOKIE=1 npm run service
```

원점 주소에는 경로나 마지막 `/`를 넣지 않는다. 새 계정의 최초 연결에는 32자 이상의 새로운
`OVERNIGHT_SETUP_TOKEN`이 필요하다. 운영 환경의 `OVERNIGHT_MASTER_KEY`는 기존 DB에 쓰인
동일한 Base64 32바이트 키여야 한다. 키·연결 토큰·비밀번호를 로그나 문서로 공유하지 않는다.

- 동일 호스트에서 같은 DB를 사용하는 서버는 한 프로세스만 실행할 수 있다. PID와 소유 토큰을
  확인한 뒤 미완료 작업을 복구하므로 두 번째 서버가 실행 중인 작업을 중단 처리하지 않는다.
  이 잠금은 여러 호스트가 공유하는 디스크용이 아니다.
- 정상 종료는 새 작업을 막고 현재 처리를 마무리한다. 강제 종료·전원 중단 뒤에는 남은 작업을
  `interrupted`로 표시하며 자동 재신청하지 않는다. Mac이 꺼지면 신청 처리도 계속되지 않는다.
- 연결 토큰은 서버에서도 1년 뒤 만료된다. 시작 시 30일 지난 완전 확인 결과만 정리한다.
  `unknown`·`not_attempted`가 있는 결과와 실패·중단 기록은 기간이 지나도 보존한다.
- 인증 요청은 IP당 분당 10회, 인증된 일반 API는 계정당 분당 120회로 제한한다.
  비로그인 일반 API는 IP당 분당 120회다. 전달된 프록시 IP 헤더를 신뢰하지 않으므로
  같은 로컬 터널의 로그인 시도는 IP 제한을 공유한다.
- Host·Origin·JSON 형식과 크기, 학교 요청 목적지·응답 크기·제한 시간을 검사한다.
  로그에는 요청 ID·메서드·상태·소요 시간만 남기고 학교 응답 원문이나 인증 정보를 남기지 않는다.

## 백업과 복구

실행 중인 SQLite도 WAL의 최신 내용을 포함해 온라인 백업할 수 있다. 목적지는 원본 데이터
폴더 밖의 **아직 존재하지 않는 새 폴더**로 지정하며, 기존 백업은 덮어쓰지 않는다.

```sh
node service/backup.mjs /absolute/path/to/new-backup-directory
```

기본 원본은 `service/data`다. 별도 데이터 폴더를 사용한다면 두 번째 인수로 지정한다.
백업 폴더는 0700, DB·키·manifest는 0600 권한으로 만든다. DB 무결성과 암호문을 검증한 뒤
`manifest.json`을 마지막에 기록한다. 이 파일이 없으면 성공한 백업으로 사용하지 않는다.

일치하는 로컬 `master.key`는 원본 그대로 함께 보존한다. 환경변수로만 관리되는 키는 파일로
내보내지 않으며 manifest의 `requiresExternalKey`가 `true`다. 이 경우 동일한 키를 별도 비밀
저장소에 보관해야 복구할 수 있다. 백업 폴더와 키는 저장소 커밋·공개 배포 대상에 포함하지 않는다.

복구 순서는 다음과 같다.

1. 처리 중인 신청을 확인하고 서버를 정상 종료한다. 같은 DB를 사용하는 프로세스가 없음을 확인한다.
2. 기존 데이터 폴더 전체를 별도 위치에 보관한다. 기존 DB·키·WAL을 삭제하거나 백업으로 덮어쓰지 않는다.
3. 완료된 백업의 manifest와 DB·원래 키를 확인한다. 백업 원본도 유지한 채 새 복구 폴더로
   `overnight.db`와 해당 `master.key`를 복사한다. 환경변수 키 방식은 원래 키를 다시 주입한다.
   온라인 백업 DB에 기존 실행 폴더의 WAL·SHM 파일을 섞지 않는다.
4. 복구 폴더 권한을 0700, DB·키를 0600으로 설정하고 `OVERNIGHT_DATA_DIR`로 새 폴더를 지정해
   서버를 실행한다. 키 불일치나 실행 잠금 오류가 나면 원인을 확인하고 새 키로 대체하지 않는다.
5. `/api/health`, 계정 연결 상태, 기존 작업 결과와 미리보기를 확인한다. 불확실했던 신청은
   학교 내역과 대조하며, 복구 확인을 위해 새 신청을 전송하지 않는다.

## 검증과 실행 환경 반영 상태

```sh
npm run test:service
```

실행되는 검증 파일은 다음과 같다.

| 파일 | 검증 범위 |
| --- | --- |
| `extension/test_core.mjs` | 날짜·중복·한국 시간 마감·날짜 입력 없는 프리셋 |
| `service/test.mjs` | HTTP 처리, 계정 연결·재연결, 미리보기 고정, 단건·일괄 재접수와 복구 |
| `service/test_store.mjs` | 기존 DB 보존, 키·만료, 토큰 복구, 작업 이력·상태·보존, 단일 실행 잠금 |
| `service/test_backup.mjs` | 열린 WAL DB 백업·복구, 파일 권한, 덮어쓰기 거부, 외부 키 미노출 |
| `service/test_portal.mjs` | 학교 XML·쿠키·전송 검증, 응답 유실·불명확한 저장·중단 |
| `service/test_http.mjs` | 실제 로컬 소켓, 보안 헤더·요청 제한, 계정별 접근과 복구·작업 처리 |
| `service/test_ui.mjs` | 폼 제출, 입력 잠금, 진행 결과·이력·중단·다시 연결·로그아웃 |

위 7개 자동 검증은 기본 시간대와 `TZ=America/New_York`에서 모두 통과했다.
자동 검증과 브라우저 QA는 가짜 학교 포털과 임시 DB만 대상으로 한다. 실제 브라우저에서
일괄 미리보기·접수·즉시 중단·새로고침·로그아웃·재연결 후 이력 복구를 확인했다.
중단 시 현재 처리 건까지만 확인하고 21건이 미처리로 남는 것을 확인했으며,
좁은 화면에서도 가로 넘침 없이 주요 버튼 높이 44px 이상을 유지했다.

별도의 실계정 읽기 전용 검증에서 학교 로그인·생활관 정보·기존 신청 7건 조회를 확인했다.
저장 메서드를 차단하고 허용된 조회 요청만 사용했으며, 실제 학교에 추가 외박신청은 보내지 않았다.

**2026-09-19 실행 서버 반영 완료.** 온라인 백업을 만든 뒤 기존 서버를 정상 종료하고
최신 서버를 같은 8787 포트로 실행했다. 로컬·공개 HTTPS `/api/health`가 정상 응답하며,
공개 `/api/session`도 정상 응답한다. 쿠키 없는 검증 요청의 `connected: false`는 정상이다.
백업과 비교해 기존 프로필·세션 토큰 해시·암호문·키가 그대로임을 확인했다.
DB 무결성 검사도 통과했고 새 작업 테이블은 비어 있다. 실계정 브라우저의 신청 버튼은 누르지 않았다.

현재 주소: [외박신청 서비스](https://street-publishers-albert-fossil.trycloudflare.com).
임시 터널 주소는 터널 재실행 시 바뀔 수 있다. 배포 전 백업은 저장소 밖의 보호된
`work/private-backup-20260919-before-hardening` 폴더에 보관했다.

학교 SSO·API·생활관 일정이 변경되면 실제 조회를 기준으로 연동을 다시 검증해야 한다.
공개 다중 사용자 운영에는 지속 실행 환경, 원래 키의 별도 보관, HTTPS 주소와 신뢰할 프록시
구성이 필요하다. 현재 구현의 잠금과 요청 제한은 단일 호스트·프로세스 기준이다.
